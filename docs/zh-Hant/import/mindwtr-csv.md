# 匯入 Mindwtr CSV

Mindwtr 可以匯入遵循既定欄位格式的一般 CSV 檔案。對於沒有專屬匯入工具、但能匯出試算表的應用程式，這就是通用做法。

支援的來源：

- 單一 `.csv` 檔案
- 內含一個或多個 CSV 檔案的 `.zip` 壓縮檔

桌面版與行動版都可從**設定 → 資料 → 從 Mindwtr CSV 匯入**執行匯入。在寫入任何內容之前，Mindwtr 會先顯示含數量與警告的預覽。

## 何時該用這個匯入工具

若[從其他應用程式匯入資料](/zh-Hant/import/)已列出你的應用程式，請優先使用對應的原生匯入工具：它們直接讀取該應用程式自己的匯出檔，也已熟悉其中的各種細節。

當清單中沒有你的應用程式時，就改用 Mindwtr CSV。先匯出該應用程式產生的 CSV，在試算表軟體中把標題列的欄位名稱改成下列名稱，再匯入結果檔案。相較於貼上一串標題，這種做法能保留更多內容：專案、分區、領域、狀態、日期、標籤、情境、檢查清單與重複規則都能一併帶過去。

## 檔案格式

- **編碼：** UTF-8。位元組順序記號會自動移除。其他編碼會以寬鬆方式解碼，可能遺失重音字元，因此只要試算表軟體允許，請另存為 UTF-8。
- **分隔符號：** 依第一行非空白內容自動判斷，逗號、分號與 Tab 字元都可以。
- **引號：** 採用一般 CSV 規則。當值含有分隔符號、換行或引號時，請用 `"` 括住，值內部的引號寫成 `""`。
- **標題列：** 必要。其中必須有 `Title`，否則匯入會直接顯示錯誤，而不會自行猜測。
- **欄位名稱：** 比對時不分大小寫與順序。無論 Mindwtr 介面設定為哪種語言，欄位名稱一律使用下列英文名稱。
- **未知欄位：** 會被忽略，並以一則警告說明忽略了幾個。
- **空白列：** 直接略過，不另提示。有內容但沒有標題的列會被略過並提出警告。
- **NULL 儲存格：** 只包含 `NULL` 的儲存格會視為空值。從 SQL 資料庫匯出的 CSV 檔就是這樣表示缺漏值的。

## 欄位參考

除 `Title` 外，所有欄位都是選用的，只需保留你確實會用到的欄位。

| 欄位 | 可接受的值 | Mindwtr 的處理方式 |
| --- | --- | --- |
| `Title` | 任意文字 | 必要，即任務標題。 |
| `Description` | 任意文字 | 任務描述。位於引號內的值可保留換行。 |
| `Status` | `inbox`、`next`、`waiting`、`someday`、`reference`、`done`、`archived` | 不分大小寫。留空時：若已設定 `Completed At`，狀態為 `done`；否則該列若指定專案則為 `next`；再否則為 `inbox`。無法辨識的值會變成 `inbox` 並提出警告。 |
| `Project` | 專案名稱 | 只建立一次該專案，並把任務放入其中。名稱比對時不分大小寫。 |
| `Section` | 該列所屬專案中的分區名稱 | 需要同一列有 `Project`。若沒有，該值會被忽略並提出警告。 |
| `Area` | 領域名稱 | 該列若有 `Project`，則由領域容納該專案；否則任務本身歸入該領域。 |
| `Contexts` | 以逗號或分號分隔的名稱 | 缺少開頭的 `@` 時自動補上，並移除重複項目。 |
| `Tags` | 以逗號或分號分隔的名稱 | 缺少開頭的 `#` 時自動補上，標籤轉為小寫，並移除重複項目。 |
| `Assigned To` | 人員姓名 | 設定負責人，這也是「等待」清單的資料來源。 |
| `Priority` | `high`、`medium`、`low` 或 `1`、`2`、`3` | 其他內容一律不設定優先順序。 |
| `Energy` | `high`、`medium`、`low` | 其他內容一律不設定精力等級。 |
| `Start Date` | 日期，可含時間 | 開始日期。在該日期到來前，任務不會出現在「專注」中。 |
| `Due Date` | 日期，可含時間 | 截止期限。 |
| `Review Date` | 日期，可含時間 | 供日後重新考慮的複查日期。 |
| `Completed At` | 含時間的日期 | 完成時間戳記。它也會把空白的 `Status` 變成 `done`，而且只有在最終狀態為 `done` 或 `archived` 時才會保留。 |
| `Created At` | 含時間的日期 | 建立時間戳記。留空時以匯入當下為準。 |
| `Checklist` | 以換行或 `\|` 分隔的項目 | 成為該任務的檢查清單。寫成 `[x] Buy stamps` 的項目一開始即為已完成；`[ ] Buy stamps` 與只寫 `Buy stamps` 則為未完成。含檢查項目的任務會變成清單型任務。 |
| `Location` | 任意文字 | 任務的地點欄位。 |
| `Order` | 數字 | 在同一專案、領域或收集箱內排序任務。沒有數字或數字相同的列，會維持它們在檔案中的先後順序。 |
| `ID` | 任意穩定識別碼 | 為該列提供可長期沿用的身分，方便重新匯入。若某個值重複了同一次匯入中較早的列，該列會被捨棄並提出警告。 |
| `Recurrence` | 形如 `FREQ=WEEKLY;BYDAY=MO,TH` 的重複規則 | 設定任務的重複方式。附加 `;X-MINDWTR-STRATEGY=FLUID`，重複就從你完成任務當天起算，而非從任務日期起算。Mindwtr 無法表達的規則會被略過，並提出指明所在列的警告，該任務將不帶重複規則匯入。 |

## 日期與時間

- 像 `2026-09-01` 這種只有日期的值會維持純日期，Mindwtr 不會替它補上午夜時間。
- 像 `2026-09-05 14:30` 這種不含時區的日期時間，會原樣保留這個時鐘時間。
- 以 `Z` 結尾或帶有 `+02:00` 之類位移的值，會依其所指的精確時刻儲存。
- `Created At` 與 `Completed At` 一律以精確時刻儲存，因為它們記錄的是某件事實際發生的時間。
- Mindwtr 無法解析的值會留空，預覽會說明略過了幾個。
- 接受 SQL 風格的時間戳記，例如 `2026-02-21 22:44:00.6390000 +00:00`：多餘的小數位和時區偏移前的空格會自動正規化。

ISO 8601（`YYYY-MM-DD`）是最保險的寫法。其他格式也會嘗試解析，但試算表中仍使用當地日期格式的欄位，是值被略過最常見的原因。

## 完整範例

```csv
Title,Description,Status,Project,Section,Area,Contexts,Tags,Priority,Start Date,Due Date,Checklist,ID
Book the venue,Needs 60 seats,next,Team Offsite,Logistics,Work,@phone,#offsite,high,2026-09-01,2026-09-12,[x] Shortlist venues|[ ] Call first choice,offsite-1
Draft the agenda,,next,Team Offsite,Programme,Work,@computer,"#offsite, #writing",medium,,2026-09-20,,offsite-2
Buy a whiteboard,,inbox,,,,@errands,,,,,,offsite-3
```

這個檔案會建立一個領域，其中含有一個帶兩個分區的專案、該專案下的兩項任務、第一項任務上的兩項檢查清單，以及一項獨立的收集箱任務。

## 匯入流程

1. 開啟**設定 → 資料 → 從 Mindwtr CSV 匯入**。
2. 選擇你的 `.csv` 或 `.zip` 檔案。
3. 詳讀預覽。其中會列出將建立多少任務、領域、專案、分區與檢查項目，有多少任務不屬於任何專案，前幾個專案及其任務數，以及所有警告。
4. 確認匯入；若數量看起來不對，請取消。

Mindwtr 會在寫入前儲存一份復原快照。若結果不如預期，可從**設定 → 同步 → 復原快照**還原。

## 重新匯入同一個檔案

Mindwtr 會為每一列賦予穩定的身分，因此同一個檔案匯入兩次不會產生重複內容。

- 有 `ID` 欄位時，身分以該值為準，因此修正後再次匯出仍會對應到相同的任務。
- 沒有 `ID` 欄位時，身分取決於該列在檔案中的位置（在 ZIP 中還包含其所屬檔案）。重新匯入完全相同的檔案很安全，但若匯出檔中插入或刪除了列，就無法再對齊，會產生重複任務。
- 已存在的列會被略過，而不會更新。匯入絕不會覆寫你之後在應用程式中編輯過的任務。
- 刪除會被尊重。若你刪除了匯入的專案後再次匯入該檔案，專案不會重新建立，其中的列會在沒有該專案的情況下匯入。
- 若匯入的領域或專案名稱已屬於其他項目，新項目的名稱後會加上 `(Mindwtr CSV)`，並以警告說明。

## 從 Mindwtr 匯出

Mindwtr 也會寫出同一種格式，因此來回的路徑是完整的。**設定 → 資料 → 備份 → 匯出 CSV** 會把你目前的任務儲存為一個 CSV 檔案，桌面版與行動版皆可使用。

- 在桌面版，任務清單工具列中的**匯出 CSV**按鈕只會匯出該清單目前顯示的內容——經過篩選、搜尋與領域選擇之後剩下的列。摺疊的群組仍會包含在內：摺疊只是把群組收起來，並不會把它排除。
- `ID` 欄位一律會寫出，因此重新匯入不會產生重複：`ID` 與既有任務相同的列會被略過並顯示警告。對匯出檔所做的修改**不會**回寫到應用程式中，請直接在應用程式內修改這些任務。上文關於識別的說明可直接套用。
- 已刪除的任務永遠不會匯出。該格式沒有對應的欄位，這樣的列會在下次匯入時變回一筆使用中的任務。
- 重複規則會寫成匯入工具可以讀回的重複規則，因此來回一趟也不會遺失。已完成的計次進度不會寫出，匯入後的重複會重新開始一輪新的序列。
- 若需要包含設定與已刪除項目紀錄的完整副本，請改用 JSON [備份](/zh-Hant/data-sync/backup-restore)。

## 這個匯入工具不會做的事

- **Mindwtr 無法表達的重複規則。** 使用 `BYSETPOS` 的規則，或每天重複多次的規則，會連同所在列一併提示，其任務不帶重複規則匯入，絕不會退而求其次地近似成別的規則。
- **子任務階層。** 沒有上層任務欄位。請用 `Checklist` 表示一項任務內部的步驟，並用 `Section` 在專案內分組。
- **附件。** CSV 中的檔案路徑或網址只是文字，不會下載或複製任何內容。

## 可能出現的警告

警告會依整次匯入統計，並連同數量顯示一次，不會逐列提示。無法讀懂的重複規則會額外多出一列，指明最先出現的三列：

- 已忽略未知欄位
- 有狀態無法對應，已匯入收集箱
- 有 `Section` 值因所在列沒有 `Project` 而被忽略
- 有 `Recurrence` 規則無法讀懂，相應任務不帶重複規則匯入
- 有日期值無法解析，已略過
- 有列因 `ID` 與較早的列重複而被捨棄
- 已略過沒有標題的列
- 為避免名稱衝突，已重新命名匯入的領域或專案
- 已略過 ZIP 中的非 CSV 檔案
- 已略過壓縮檔中巢狀的 ZIP 檔案
- 某個 CSV 以未閉合的引號欄位結束，已盡力匯入
- 某個 CSV 檔案無法解析，已略過

## 提示

- 先匯入一份五列的測試檔，確認對應無誤後，再搬移數百列資料。
- 若日後有可能調整匯出內容並再次匯入，請加上 `ID` 欄位。
- 若來源中沒有對應欄位，就讓 `Status` 留空。預設會把專案工作放入下一步行動，其餘放入收集箱，等你釐清。
- 在核對結果之前，請保留原始匯出檔與復原快照。
- 匯入的 `done` 與 `archived` 任務會顯示在「已完成」和「封存」檢視中，而不是所屬專案的任務清單裡——專案頁面只顯示未完成的工作。
