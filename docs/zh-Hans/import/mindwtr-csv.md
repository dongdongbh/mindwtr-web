# 从 Mindwtr CSV 导入

Mindwtr 可以导入遵循既定列格式的普通 CSV 文件。对于没有专属导入器、但能导出电子表格的应用，这就是通用路径。

支持的来源：

- 单个 `.csv` 文件
- 包含一个或多个 CSV 文件的 `.zip` 压缩包

桌面端和移动端都可从**设置 → 数据 → 从 Mindwtr CSV 导入**执行导入。在写入任何内容之前，Mindwtr 会先显示带数量和警告的预览。

## 何时使用这个导入器

如果[从其他应用导入数据](/zh-Hans/import/)中列出了你的应用，请优先使用对应的原生导入器：它们直接读取该应用自己的导出文件，也已经了解其中的各种特殊之处。

当列表中没有你的应用时，就使用 Mindwtr CSV。先导出该应用生成的 CSV，在电子表格软件中把表头单元格改成下文的列名，然后导入结果文件。相比粘贴一串标题，这种方式能保留多得多的内容：项目、分区、领域、状态、日期、标签、情境和检查清单都能一并迁移。

## 文件格式

- **编码：** UTF-8。字节顺序标记会被自动去除。其他编码会以宽松方式解码，可能丢失带重音的字符，因此只要电子表格软件允许，请另存为 UTF-8。
- **分隔符：** 根据第一行非空内容自动识别，逗号、分号和制表符都可以。
- **引号：** 遵循常规 CSV 规则。当某个值包含分隔符、换行或引号时，请用 `"` 括起来，值内部的引号写成 `""`。
- **表头行：** 必需。其中必须包含 `Title`，否则导入会直接报错，而不会去猜测。
- **列名：** 匹配时忽略大小写和顺序。无论 Mindwtr 界面设置为哪种语言，列名始终使用下文的英文名称。
- **未知列：** 会被忽略，并以一条警告说明忽略了多少列。
- **空行：** 直接跳过，不作提示。有内容但没有标题的行会被跳过，并给出警告。
- **NULL 单元格：** 只包含 `NULL` 的单元格按空值处理。从 SQL 数据库导出的 CSV 文件就是这样表示缺失值的。

## 列参考

除 `Title` 外，所有列都是可选的，只需保留你确实用到的列。

| 列 | 可接受的值 | Mindwtr 的处理方式 |
| --- | --- | --- |
| `Title` | 任意文本 | 必需，即任务标题。 |
| `Description` | 任意文本 | 任务描述。位于引号内的值可以保留换行。 |
| `Status` | `inbox`、`next`、`waiting`、`someday`、`reference`、`done`、`archived` | 忽略大小写。留空时：若设置了 `Completed At`，状态为 `done`；否则该行若指定了项目则为 `next`；再否则为 `inbox`。无法识别的值会变成 `inbox` 并给出警告。 |
| `Project` | 项目名称 | 只创建一次该项目，并把任务放入其中。名称匹配时忽略大小写。 |
| `Section` | 该行所属项目内的分区名称 | 需要同一行中有 `Project`。缺少时该值会被忽略并给出警告。 |
| `Area` | 领域名称 | 该行若有 `Project`，则由领域容纳该项目；否则任务本身归入该领域。 |
| `Contexts` | 以逗号或分号分隔的名称 | 缺少开头的 `@` 时自动补上，并去除重复项。 |
| `Tags` | 以逗号或分号分隔的名称 | 缺少开头的 `#` 时自动补上，标签转为小写，并去除重复项。 |
| `Assigned To` | 人员姓名 | 设置负责人，这也是「等待」清单的数据来源。 |
| `Priority` | `high`、`medium`、`low` 或 `1`、`2`、`3` | 其他内容一律不设置优先级。 |
| `Energy` | `high`、`medium`、`low` | 其他内容一律不设置精力等级。 |
| `Start Date` | 日期，可带时间 | 开始日期。在该日期到来前，任务不会出现在焦点中。 |
| `Due Date` | 日期，可带时间 | 截止期限。 |
| `Review Date` | 日期，可带时间 | 用于日后重新考虑的复查日期。 |
| `Completed At` | 带时间的日期 | 完成时间戳。它还会把空的 `Status` 变成 `done`，并且只在最终状态为 `done` 或 `archived` 时才保留。 |
| `Created At` | 带时间的日期 | 创建时间戳。留空时以导入时刻为准。 |
| `Checklist` | 以换行或 `\|` 分隔的条目 | 成为该任务的检查清单。写成 `[x] Buy stamps` 的条目初始为已完成；`[ ] Buy stamps` 和只写 `Buy stamps` 则为未完成。含检查项的任务会变成清单型任务。 |
| `Location` | 任意文本 | 任务的地点字段。 |
| `Order` | 数字 | 在同一项目、领域或收集箱内对任务排序。没有数字或数字相同的行，保持它们在文件中的先后顺序。 |
| `ID` | 任意稳定标识 | 为该行提供可长期沿用的身份，便于重新导入。若某个值重复了同一次导入中较早的行，该行会被丢弃并给出警告。 |
| `Recurrence` | 任意文本 | 会被识别，因此不会算作未知列，但其值会被忽略并给出警告。 |

## 日期与时间

- 像 `2026-09-01` 这样只有日期的值仍是纯日期，Mindwtr 不会为它补上午夜时间。
- 像 `2026-09-05 14:30` 这样不带时区的日期时间，会原样保留这一挂钟时间。
- 以 `Z` 结尾或带 `+02:00` 之类偏移量的值，会按其所指的确切时刻保存。
- `Created At` 和 `Completed At` 始终按确切时刻保存，因为它们记录的是某件事实际发生的时间。
- Mindwtr 无法解析的值会留空，预览中会说明跳过了多少个。
- 接受 SQL 风格的时间戳，例如 `2026-02-21 22:44:00.6390000 +00:00`：多余的小数位和时区偏移前的空格会被自动规范化。

ISO 8601（`YYYY-MM-DD`）是最稳妥的写法。其他格式也会尝试解析，但表格中仍使用本地化日期格式的列，是导致值被跳过的最常见原因。

## 完整示例

```csv
Title,Description,Status,Project,Section,Area,Contexts,Tags,Priority,Start Date,Due Date,Checklist,ID
Book the venue,Needs 60 seats,next,Team Offsite,Logistics,Work,@phone,#offsite,high,2026-09-01,2026-09-12,[x] Shortlist venues|[ ] Call first choice,offsite-1
Draft the agenda,,next,Team Offsite,Programme,Work,@computer,"#offsite, #writing",medium,,2026-09-20,,offsite-2
Buy a whiteboard,,inbox,,,,@errands,,,,,,offsite-3
```

这个文件会创建一个领域，其中包含一个带两个分区的项目、该项目下的两项任务、第一项任务上的一份两条检查项清单，以及一项独立的收集箱任务。

## 导入流程

1. 打开**设置 → 数据 → 从 Mindwtr CSV 导入**。
2. 选择你的 `.csv` 或 `.zip` 文件。
3. 阅读预览。其中会列出将创建多少任务、领域、项目、分区和检查项，有多少任务不属于任何项目，前几个项目及其任务数量，以及全部警告。
4. 确认导入；若数量看起来不对，请取消。

Mindwtr 会在写入前保存一份恢复快照。如果结果不符合预期，可从**设置 → 同步 → 恢复快照**还原。

## 重新导入同一个文件

Mindwtr 会为每一行赋予稳定的身份，因此同一个文件导入两次不会产生重复内容。

- 有 `ID` 列时，身份以该值为准，因此修正后再次导出仍会对应到同样的任务。
- 没有 `ID` 列时，身份取决于该行在文件中的位置（在 ZIP 中还包括所属文件）。重新导入完全相同的文件是安全的，但若导出文件中插入或删除了行，就无法再对齐，会产生重复任务。
- 已存在的行会被跳过，而不会被更新。导入绝不会覆盖你之后在应用中编辑过的任务。
- 删除操作会被尊重。如果你删除了导入的项目再次导入该文件，项目不会被重新创建，其中的行会在没有该项目的情况下导入。
- 如果导入的领域或项目名称已属于其他条目，新建的条目名称后会加上 `(Mindwtr CSV)`，并给出相应警告。

## 从 Mindwtr 导出

Mindwtr 也会写出同一种格式，因此往返路径是完整的。**设置 → 数据 → 备份 → 导出 CSV** 会把你当前的任务保存为一个 CSV 文件，桌面端和移动端都可以。

- `ID` 列始终会写出，因此重新导入不会产生重复：`ID` 与已有任务相同的行会被跳过并给出警告。对导出文件所做的修改**不会**回写到应用中，请直接在应用内修改这些任务。上文关于标识的说明可直接套用。
- 已删除的任务从不导出。该格式没有对应的列，这样的行会在下次导入时变回一条活动任务。
- 重复规则不会写出，这与导入器读取的内容一致。重复仍然在应用内设置。
- 若需要包含设置和已删除项历史的完整副本，请改用 JSON [备份](/zh-Hans/data-sync/backup-restore)。

## 这个导入器不做的事

- **重复规则。** CSV 不会生成重复任务，请在导入后于应用中设置。
- **子任务层级。** 没有父任务列。请用 `Checklist` 表示一项任务内部的步骤，用 `Section` 在项目内分组。
- **附件。** CSV 中的文件路径或网址只是文本，不会被下载或复制。

## 可能出现的警告

警告按整次导入统计，并连同数量显示一次，不会逐行提示：

- 已忽略未知列
- 有状态无法映射，已导入收集箱
- 有 `Section` 值因所在行没有 `Project` 而被忽略
- 已忽略 `Recurrence` 值
- 有日期值无法解析，已跳过
- 有行因 `ID` 与较早的行重复而被丢弃
- 已跳过没有标题的行
- 为避免名称冲突，重命名了导入的领域或项目
- 已跳过 ZIP 中的非 CSV 文件
- 已跳过压缩包中嵌套的 ZIP 文件
- 某个 CSV 以未闭合的引号字段结束，已尽力导入
- 某个 CSV 文件无法解析，已跳过

## 提示

- 先导入一份五行的测试文件，确认映射无误后，再迁移成百上千行。
- 如果日后有可能调整导出内容并再次导入，请加上 `ID` 列。
- 如果来源中没有对应字段，就让 `Status` 留空。默认规则会把项目工作放入下一步行动，其余放入收集箱，等待你厘清。
- 在核对结果之前，请保留原始导出文件和恢复快照。
- 导入的 `done` 和 `archived` 任务显示在“已完成”和“归档”视图中，而不是所属项目的任务列表里——项目页面只显示未完成的工作。
